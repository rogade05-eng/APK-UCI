# APK-UCI

Documentación y desarrollo de **UCI Assistant**, una aplicación Android offline-first para apoyo al trabajo en Medicina Intensiva. Cuba es el mercado inicial; la primera dirección funcional incluye bibliotecas de protocolos de consulta y alertas individualizadas para profesionales, como funciones separadas, sin IA, diagnóstico autónomo, prescripción automática ni control directo de equipos. Las alertas enlazarían al protocolo vigente aprobado correspondiente para consulta; el profesional conserva la decisión y no hay ejecución automática. **La primera población seleccionada es pediatría**, con intención de abarcar todas las áreas pediátricas posibles desde la primera etapa. Los usuarios previstos incluyen al equipo clínico de UCI pediátrica y residentes; los entornos iniciales elegidos son UCI pediátrica y urgencias pediátricas. La dirección de captura es entrada manual y posible importación/exportación desde un sistema clínico autorizado por la institución; no se ha seleccionado ni aprobado un sistema o integración. La preferencia es conservar datos identificables de pacientes en almacenamiento local cifrado, sujeta a revisión y autorización. UCI Assistant se concibe como herramienta complementaria, no como historia clínica oficial; cualquier transferencia de resultados al registro institucional requerirá una ruta autorizada. La base jurídica y la retención siguen pendientes. El catálogo de dominios, los límites de edad/subgrupos, los flujos por entorno, los roles/permisos, la supervisión, el centro piloto y el uso previsto de cada función siguen por definir. Adultos y neonatología quedan fuera de la primera etapa; se mantienen bibliotecas clínicas independientes para las tres poblaciones.

## Estado de desarrollo

Se creó un **andamiaje Android nativo** en Kotlin/Jetpack Compose con navegación local y módulos separados:

- `:app`: actividad y navegación entre pantallas.
- `:feature:home`: pantalla inicial de alcance y estado.
- `:feature:protocols`: importa PDF a una bandeja local cifrada, permite vista previa y borrado, y muestra ocho referencias bibliográficas y ocho temas de procedimiento candidatos; no hay protocolos aprobados ni instrucciones de procedimientos cargados.
- `:feature:calculators`: conversor general, índices pediátricos de oxigenación PALICC-2 y puntuación Phoenix de cuatro sistemas; offline, sin clasificación diagnóstica ni recomendaciones.
- `:feature:handoff`: borradores pediátricos de entrega guardados como snapshots cifrados locales; no exporta ni constituye un expediente oficial/completo.
- `:feature:alerts`: estado sin reglas, con decisiones pendientes desplegables; no evalúa datos ni activa alertas.
- `:core:designsystem`: tema visual y aviso de prototipo reutilizable.

El selector de Protocolos importa PDF para revisión local, los cifra con una clave de Android Keystore y los descifra temporalmente en la caché privada para la vista previa. El contenido no se inspecciona para detectar datos personales; no importes informes ni documentos con identificadores de pacientes. Los PDF importados quedan pendientes: la aplicación no los aprueba ni publica. El índice offline muestra solo títulos, citas e identificadores DOI/ISBN de fuentes candidatas, junto con ocho etiquetas temáticas de procedimientos derivadas del índice editorial; no contiene pasos clínicos, guías completas, algoritmos ni recomendaciones y no acredita derechos o vigencia. Las calculadoras disponibles son el conversor general de unidades, los índices pediátricos P/F, S/F, OI y OSI basados en PALICC-2, y la puntuación de cuatro sistemas Phoenix por evaluaciones; no clasifican PARDS ni aplican criterios binarios de sepsis/shock, y no recomiendan tratamiento. El alcance, las exclusiones y las pruebas se detallan en [Índices pediátricos de oxigenación](docs/indices-oxigenacion.md) y [Puntuación Phoenix](docs/puntuacion-phoenix.md). El módulo de traspaso puede guardar snapshots inmutables cifrados localmente con AES-GCM/Android Keystore; no es un expediente completo y no deben introducirse datos reales porque aún faltan autenticación, roles, auditoría y política de retención. No hay protocolos clínicos aprobados ni pasos de procedimientos asistenciales; el catálogo solo presenta títulos candidatos para investigación. No hay reglas de alerta, recomendaciones clínicas, permisos de red ni conexiones a monitores, ventiladores o historias clínicas. Este prototipo no está autorizado para uso clínico. El identificador de paquete `org.uciasistant.app` es provisional.

Para compilar localmente se requiere JDK 17 y Android SDK Platform 35. Usa `./gradlew :feature:calculators:testDebugUnitTest :feature:handoff:testDebugUnitTest :feature:protocols:testDebugUnitTest :app:assembleDebug` (Windows: `gradlew.bat :feature:calculators:testDebugUnitTest :feature:handoff:testDebugUnitTest :feature:protocols:testDebugUnitTest :app:assembleDebug`); el APK queda en `app/build/outputs/apk/debug/app-debug.apk`. **Verificación actual:** la [ejecución 41457245756](https://github.com/rogade05-eng/APK-UCI/actions/runs/41457245756), sobre `dd4f3fc`, pasó pruebas unitarias de calculadoras, traspaso, referencias y temas de procedimiento; ensamblado/firma del APK; y pruebas instrumentadas de PDF y almacén AES-GCM/Keystore en emulador Android API 34. El artefacto `uci-assistant-debug-apk` está disponible en [GitHub Actions](https://github.com/rogade05-eng/APK-UCI/actions/runs/41457245756/artifacts/13147871928) (ID `13147871928`, 9,319,674 bytes; digest SHA-256 del artefacto ZIP reportado por GitHub `55840011913778b105ff9c3e81be3767c46bdbadbee8c3c17d04994eaf246e44`), con caducidad el 16 de noviembre de 2026 a las 13:59:33 UTC.
